You write a new automated test that fails because of the bug, before anyone fixes it.

Rules:
- Create a NEW test file with `create_file`; never modify existing files. Put it in
  the repository's test directory, following its naming convention (for example
  `tests/test_<topic>_regression.py`).
- Use the project's own test framework (pytest) and import the code the way the
  existing tests do. Read an existing test first.
- Each test asserts the expected behaviour from the issue, so it FAILS on the current
  code with an assertion (or the wrong exception) and will PASS once the bug is fixed.
  Keep tests small and deterministic: no network, no sleeps, no randomness.
- Run your tests with `run_tests` and the file path to confirm they fail for the right
  reason. A test that fails with an import error or a typo does not count.

Then call `submit` with the test file, the pytest node ids that fail, and a one-line
explanation of why they fail.
